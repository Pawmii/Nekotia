# Nekotia — Roadmap

Цель: настоящая ОС для x86_64 (QEMU и реальное железо), ядро и системные программы которой пишутся на C#
и транслируются в C++. Всё, что критично к памяти и железу, живёт в C++-базе (`runtime/`) и доступно из C#
через `[Native]`. Каждая фаза заканчивается проверкой в QEMU.

Обозначения: `[x]` готово, `[ ]` запланировано, `(*)` — растяжимые цели.

---

- [x] Маппинг: namespace, static class, struct (поля, методы, конструкторы, свойства, операторы), enum (+ битовые операторы),
      указатели, `fixed`-буферы, `stackalloc`, generic-методы → шаблоны, function pointers, `ref/out/in`
- [x] Явные касты там, где правила продвижения целых в C# и C++ расходятся (`uint + int` → `long`)
- [x] `#line` директивы: ошибки clang, `addr2line` и gdb указывают на C#-строки
- [x] Диагностика `NEKO0xxx` с подсказками (классы, foreach, строки, float, try/throw…), вывод в формате MSBuild и JSON
- [x] Сахар `.neko`: `asm { }`, `asm "…"`, `defer`, `unless`, `loop`, `for T i in a..b` / `a..=b`, `@entry @packed @inline @noreturn @native @align`
- [x] Makefile: ELF, ISO (Limine, BIOS + UEFI), QEMU, OVMF, host-режим с ASan/UBSan
- [x] Отладка: `make debug` (`-O0`, gdb-сервер), F5 в VS Code, брейкпоинты по строкам `.cs`/`.neko`
- [x] VS Code: грамматика `.neko`, сниппеты, hover, диагностика при сохранении, команды, переход к сгенерированному C++
- [x] IDE-проекты (`Nekotia.slnx`) с десугарингом `.neko` для IntelliSense в `.cs`

**Ядро**
- [x] Загрузка по протоколу Limine (base revision 3), higher-half, HHDM, карта памяти, framebuffer, cmdline
- [x] COM1 serial, форматированный вывод
- [x] IDT + обработчики 32 исключений с дампом регистров, `cr2`, причиной page fault
- [x] Куча: first-fit free list, split/coalesce, выравнивание 16, магия в заголовках, детект double free, `check()`
- [x] Физический page allocator (стек свободных фреймов)
- [x] `operator new/delete`, `memcpy/memset/memmove/memcmp`, `__init_array`
- [x] Самотесты при загрузке (язык, сахар, куча, страницы)

## Фаза 4 — Многозадачность ✅

- [x] Потоки ядра: свой стек с guard-страницей, переключение контекста на asm, повторное использование стеков
- [x] Вытесняющий планировщик: 3 приоритета, round-robin с квантом 10 мс, idle-поток, учёт CPU-времени
- [x] SpinLock (рекурсивный, с отключением прерываний), Mutex, Semaphore (signal из IRQ); сахар `lock (m) { }` в .neko
- [x] Обнаружение deadlock: повторная блокировка и циклы ожидания → STOP 0xE5 DEADLOCK с цепочкой потоков
- [x] FPU/SSE: включается до C++-кода, сохраняется при каждом прерывании и переключении → `float`/`double`, `Maths`
- [x] Потокобезопасная куча и вывод; клавиатура будит shell через семафор
- [x] SMP: запуск AP через Limine MP (до 16 CPU), per-CPU данные через GS, свои GDT/TSS/LAPIC-таймер на каждом CPU,
      общий планировщик (блокировка держится через переключение контекста), IPI: reschedule, TLB shootdown, NMI-остановка при падении
- [x] Приоритетное наследование в Mutex: владелец (и цепочка до 8 владельцев) работает с приоритетом самого
      срочного ожидающего до `Unlock`; мьютекс достаётся самому срочному ожидающему
- [ ] AVX/XSAVE (сейчас только SSE через fxsave), per-CPU кэши кучи

## Фаза 5 — Userspace ✅ (основное)

- [x] Ring 3, `syscall`/`sysret` (swapgs, свой стек ядра на поток через `TSS.rsp0`/GS), таблица системных вызовов
- [x] `[Syscall(n)]` / `@syscall(n)` — системный вызов на C# в ядре (номера от 32; ввод с клавиатуры для программ — тоже C#, через `/dev/console`)
- [x] Процессы: свои адресные пространства (общая верхняя половина), загрузчик статических ELF64 из VFS (`/bin` в initrd),
      `spawn`, `exit`, `wait`, argc/argv, куча программы (`alloc`), полное освобождение памяти при выходе, сироты → ядру
- [x] Несколько потоков в процессе (`thread_create`/`thread_exit`, `Thread.Start/Join`, `SpinLock`, `Atomic`);
      `exit` или падение любого потока завершает весь процесс
- [x] `kill`, Ctrl+C для программы на переднем плане (консоль переходит к тому, кого ждут в `wait`): прерываются
      бесконечный цикл в ring 3, `sleep`, ожидание клавиатуры и ожидание потомка (`Semaphore.WaitInterruptible`)
- [x] Исключения в ring 3 убивают только процесс (код 128 + вектор), ядро продолжает работу
- [x] SMEP/SMAP (где есть в CPU; QEMU — `-cpu qemu64,+smep,+smap`), доступ к памяти программ только через
      `copy_from_user`/`copy_to_user` с обработкой #PF (ошибка вызова вместо экрана смерти)
- [x] User SDK: nekoc с `"target": "user"` (точка входа `Main`), `runtime/user`, `sdk/Nekotia.User`, IDE-проект `user/`
- [x] Shell в userspace (`sh`) и утилиты `ls`, `ps`, `echo`, `kill`, `primes` (параллельный счёт на всех CPU);
      `init=NAME` в командной строке ядра; в shell ядра — `run`, запуск по имени, `progs`, `kill`, процессы в `ps`
- [x] Файлы в программах: 32 дескриптора на процесс, наследование 0–2 и рабочего каталога, `dup/dup2`; `sh` с `cd`,
      `> >> <` и запуском по пути; утилиты `ls`, `cat`, `mkdir`, `rm`, `mv`
- [x] futex (системные вызовы 32/33): `Thread.Join` и `SpinLock` (теперь мьютекс: спин, затем сон) без опроса
- [x] `unmap`/`protect` (34/35): страницы возвращаются ядру и переиспользуются, права страниц (только чтение и т.п.)
- [ ] Сигналы, разделяемая память, лимиты ресурсов

## Фаза 6 — Драйверы и файловые системы

- [x] PCI/PCIe перечисление: ECAM через ACPI MCFG (или порты 0xCF8), рекурсивный обход мостов, BAR с размерами,
      capabilities; `Pci` в SDK, команда `lspci [-v]`
- [x] virtio-blk (virtio 1.x modern PCI, split virtqueue, 8 запросов параллельно, MSI-X или опрос); слой блочных
      устройств (`Block`, `/dev/vda` с побайтовым доступом, RAM-диски); MSI/MSI-X в рантайме; `disks`, MSI в `irq`
- [x] AHCI (SATA): ATA-диски `sda…` (READ/WRITE DMA EXT, 48-битный LBA, FLUSH), ATAPI `cd0…` только на чтение
      (SCSI READ(10)/READ CAPACITY через PACKET), 8 слотов с DMA-буферами, MSI или опрос, восстановление порта после ошибки
- [x] NVMe: admin-очередь (IDENTIFY контроллера и пространства имён, создание очередей), пара очередей
      ввода-вывода на каждый CPU (Set Features «Number of Queues», свой вектор MSI-X и слоты у каждой), PRP-списки, бит фазы, MSI-X или опрос; `nvme0n1`, секторы 512 и 4096 байт
- [x] VFS: дерево узлов с подсчётом ссылок, ramfs, initrd (ustar-модуль Limine, copy-on-write из модуля),
      `/dev/{console,null,zero}`, рабочие каталоги, системные вызовы 16–29; команды `ls/cd/cat/mkdir/rm/mv/write/df`
- [x] Монтирование ФС в каталоги VFS (`FsOps`: ввод-вывод вне замка VFS, дерево каталогов в памяти)
- [x] FAT32: чтение/запись, длинные имена (UTF-16, кириллица), `mkfs`, `mount`/`umount`/`sync`, автомонтирование
      `vda` в `/mnt`, запись сразу на диск; `scripts/fatcheck.py` — независимая проверка образа в `make test`
- [x] Каналы: `pipe` (буфер 64 КиБ, блокирующие чтение/запись, прерываемые `kill`, EOF, broken pipe → 141),
      конвейеры `a | b | c` в `sh`; утилиты `grep`, `wc`, `head`
- [x] `/proc` на C#: version, uptime, cmdline, cpuinfo, meminfo, processes, threads, mounts, disks, pci,
      net/{dev,arp,tcp,udp} — файлы-генераторы VFS (`Vfs.CreateGenerated`)
- [ ] FAT12/16, ext2 (чтение); кэш блоков и отложенная запись
- [x] virtio-net (общий virtio-транспорт с virtio-blk) и стек TCP/IP **на C#** (`kernel/Net`): ARP, IPv4, ICMP, UDP,
      DHCP, DNS, TCP (рукопожатие, окна, повторная передача, FIN/RST, TIME_WAIT); сокеты — файловые дескрипторы,
      системные вызовы 40–48 на C# (`@syscall`); `ifconfig`, `ping`, `arp`, `netstat`; программы `httpd`, `fetch`,
      `nc`, `host`; `make run` пробрасывает localhost:8080 → :80
- [x] TCP: оценка RTT (RFC 6298, Карн), контроль перегрузки (slow start, congestion avoidance, fast retransmit/recovery
      NewReno), сборка сегментов не по порядку в кольце + SACK в обе стороны (восстановление нескольких дыр за RTT),
      масштабирование окна и буферы 128 КиБ, ACK до SND.MAX после отката; ICMP «порт недоступен»; самотест: 1 МиБ по
      loopback, теряющему каждый 9-й сегмент (`Stack.LossEvery`), — 1.3 с вместо 29
- [ ] IPv6, TCP timestamps, delayed ACK
- [x] USB: xHCI (передача от BIOS, сброс, кольца команд/событий, scratchpad, MSI-X), перечисление устройств на
      корневых портах, HID boot-клавиатура (→ скан-коды PS/2 для драйвера на C#, автоповтор через SET_IDLE) и мышь; `lsusb`
- [x] USB: хабы USB 2/3 любой глубины (route string, TT, SET_HUB_DEPTH), горячее подключение и извлечение (поток
      `usb-hub`), флешки (Bulk-Only Transport + SCSI, сбросы при stall) → блочные `usbN`, FAT32 монтируется в
      `/media/usbN` и отмонтируется при извлечении; `lsusb` деревом; самотест с хабом и флешкой за ним
- [ ] USB: изохронные устройства (звук), UAS, несколько LUN

### Принципы

1. **Железо и память — в C++, логика — в C#.** Новый примитив сначала появляется в `runtime/`, потом получает
   C#-обёртку в SDK через `[Native]`.
2. **Ошибка трансляции — ошибка компиляции.** Неподдерживаемая конструкция даёт `NEKO`-диагностику с подсказкой,
   а не неправильный C++.
3. **Семантика C# сохраняется**: продвижение целых, порядок `defer`, обнуление `stackalloc` и полей структур.
4. **Всё проверяется в QEMU** — host-режим только ускоряет цикл разработки.
